2. Lecture 06 — 재귀 & 딕셔너리 Recursion · Dictionaries

2-1. 재귀 (Recursion)

재귀 = 함수가 자기 자신을 호출하는 기법. 큰 문제를 같은 형태의 더 작은 문제로 줄여 푼다(divide/decrease-and-conquer). 반드시 두 부분이 있어야 한다:

  • base case(기저 사례) — 더 줄이지 않고 즉시 답하는 종료 조건. 없으면 무한 재귀 → RecursionError
  • recursive step(재귀 단계) — 문제를 더 작은 같은 문제로 축소하여 자기 자신 호출

곱셈: 반복 vs 재귀 (같은 일을 두 방식으로)

# 반복(iterative): a를 b번 더한다
def mult_iter(a, b):
    result = 0
    while b > 0:
        result += a
        b -= 1
    return result

# 재귀(recursive): a*b = a + a*(b-1)
def mult(a, b):
    if b == 1:          # base case
        return a
    else:               # recursive step
        return a + mult(a, b-1)

팩토리얼 & 피보나치(base case 2개)

def fact(n):            # n! = n*(n-1)*...*1
    if n == 1:
        return 1
    else:
        return n * fact(n-1)

def fib(n):             # base case가 2개!
    if n == 0 or n == 1:
        return 1
    else:
        return fib(n-1) + fib(n-2)
🧠 호출 스코프(scope)
재귀 호출은 매번 자기만의 스코프(스택 프레임)를 만든다. 그래서 각 호출의 n은 서로 안 섞이고, 호출이 값을 반환하면 제어가 이전 스코프로 돌아간다. → 시험의 “호출 추적해 출력 쓰기” 유형의 핵심.

하노이 탑 (재귀적 사고의 대표)

def printMove(fr, to):
    print('move from ' + str(fr) + ' to ' + str(to))

def Towers(n, fr, to, spare):
    if n == 1:
        printMove(fr, to)
    else:
        Towers(n-1, fr, spare, to)   # 위 n-1개를 spare로
        Towers(1, fr, to, spare)     # 제일 큰 1개를 목적지로
        Towers(n-1, spare, to, fr)   # n-1개를 다시 목적지로

비(非)숫자 재귀: 회문(palindrome) — 보조함수 중첩

def isPalindrome(s):
    def toChars(s):                  # 소문자화 + 알파벳만 남김
        s = s.lower()
        ans = ''
        for c in s:
            if c in 'abcdefghijklmnopqrstuvwxyz':
                ans = ans + c
        return ans
    def isPal(s):
        if len(s) <= 1:              # 길이 0·1이면 회문(base)
            return True
        else:                        # 양끝 같고 가운데도 회문이면 회문
            return s[0] == s[-1] and isPal(s[1:-1])
    return isPal(toChars(s))
🔑 반복 vs 재귀 비교
재귀는 더 간결·직관적(프로그래머 관점)이지만, 컴퓨터 관점에선 비효율적일 수 있다(함수 호출 비용·중복 계산). 정확성은 수학적 귀납법과 같은 논리로 보장된다: base 성립 + (k 성립 ⇒ k+1 성립).

📋 개념 Q&A — 재귀

재귀 함수가 반드시 가져야 하는 두 요소는?
base case(종료 조건)와 recursive step(더 작은 같은 문제로 축소하는 호출). base case가 없으면 무한 재귀로 RecursionError.
각 재귀 호출은 변수를 공유하는가?
아니다. 호출마다 독립된 스코프가 생겨 변수가 섞이지 않는다. 호출이 끝나 값을 반환하면 제어가 직전 스코프로 돌아간다.
피보나치 재귀가 비효율적인 이유는?
같은 값을 여러 번 중복 계산하기 때문(예: fib(34)는 11,405,773번 호출). → 딕셔너리로 memoization하면 65번으로 줄어듦.

2-2. 딕셔너리 (Dictionaries)

딕셔너리 = key–value 쌍의 모음 {key: value}. 리스트가 “정수 인덱스로 순서대로” 찾는다면, 딕셔너리는 임의의 key로 바로 찾는다(순서 개념 없음).

grades = {'Ana':'B', 'John':'A+', 'Denise':'A', 'Katy':'A'}

grades['John']          # 조회 → 'A+'   (없는 key → KeyError)
grades['Sylvan'] = 'A'  # 추가/수정
'John' in grades        # key 존재 검사 → True
del(grades['Ana'])      # 삭제
grades.keys()           # 모든 key (tuple처럼 순회 가능)
grades.values()         # 모든 value
⚠ key / value 규칙 (빈출!)
  • key는 유일(unique)하고 불변(immutable=hashable) 타입만: int, float, str, tuple, bool 가능 / list는 key 불가
  • value는 아무 타입이나 OK(중복 허용). 리스트·딕셔너리도 value 가능
  • key·value에 순서 보장 없음
리스트 list딕셔너리 dict
순서 있는 원소 시퀀스key→value 매핑
정수 인덱스로 조회임의 key로 조회
인덱스에 순서 있음순서 보장 없음
인덱스 = 정수key = 불변 타입 무엇이든

대표 예제: 노래 가사 분석 3함수 (Lec6 핵심)

# ① 빈도 딕셔너리 만들기 (str → int)
def lyrics_to_frequencies(lyrics):
    myDict = {}
    for word in lyrics:
        if word in myDict:
            myDict[word] += 1
        else:
            myDict[word] = 1
    return myDict

# ② 가장 많이 나온 단어(들)과 횟수 → (list, int)
def most_common_words(freqs):
    values = freqs.values()
    best = max(values)
    words = []
    for k in freqs:
        if freqs[k] == best:
            words.append(k)
    return (words, best)

# ③ 최소 minTimes번 이상 나온 단어들 (딕셔너리를 변형하며 반복)
def words_often(freqs, minTimes):
    result = []
    done = False
    while not done:
        temp = most_common_words(freqs)
        if temp[1] >= minTimes:
            result.append(temp)
            for w in temp[0]:
                del(freqs[w])     # 찾은 단어 삭제 후 반복
        else:
            done = True
    return result

메모이제이션: 딕셔너리로 재귀 효율화 ★

def fib_efficient(n, d):
    if n in d:                 # 이미 계산했으면 바로 반환
        return d[n]
    else:
        ans = fib_efficient(n-1, d) + fib_efficient(n-2, d)
        d[n] = ans             # 계산 결과를 저장
        return ans

d = {1:1, 2:2}
print(fib_efficient(6, d))

fib(34): 11,405,773번 → fib_efficient(34): 65번. 단, 부작용 없는(side-effect-free) 함수에만 안전하게 적용 가능.

3-3. 예외 처리 (try / except) ★

🗣 12주차 교수님
“try 안의 코드를 한 줄씩 실행하다가 에러가 나면, except 안의 코드를 실행하고 프로그램을 멈추지 않고 이어간다 — 이 부분 한국말로 중요.”
try:
    a = int(input("숫자: "))
    b = int(input("또 숫자: "))
    print("a/b =", a/b)
except ValueError:              # 특정 예외별로 분리 처리
    print("숫자로 변환 불가")
except ZeroDivisionError:
    print("0으로 못 나눔")
except:                          # 그 외 모든 예외
    print("뭔가 크게 잘못됨")
else:
    print("예외 없을 때만 실행")
finally:
    print("항상 실행 (정리용: 파일 닫기 등)")
  • else: try가 예외 없이 끝났을 때만
  • finally: 예외 발생/return/break와 무관하게 항상 실행(정리 코드)
  • raise로 직접 예외 발생: raise ValueError("메시지") — 잘못된 결과 대신 명확히 신호

에러 대처 3가지 & 대표 예제(평균 계산)

“조용히 실패(default값으로 슬쩍)=나쁨 / ‘에러값’ 반환=코드 복잡 / 예외 발생(raise)=권장”.

# 학생별 평균에서 빈 성적 리스트 → ZeroDivisionError
def avg(grades):
    try:
        return sum(grades)/len(grades)
    except ZeroDivisionError:
        print('warning: no grades data')
        return 0.0           # 옵션2: 정책 변경(0점 부여). 옵션1은 메시지만

3-4. Assertion (assert) — 방어적 프로그래밍

def avg(grades):
    assert len(grades) != 0, 'no grades data'   # 거짓이면 AssertionError로 즉시 중단
    return sum(grades)/len(grades)
  • assert 조건, "메시지" — 조건이 거짓이면 AssertionError 발생시켜 즉시 중단
  • 주로 함수 입력의 전제조건 검사(빈 리스트 방지 등), 출력·불변식 검사에도 사용 → 버그를 발생 즉시 그 자리에서 잡음
  • 예외(raise)와 차이: assert는 “있어선 안 될 상태”를 개발 중 빨리 드러내는 용도(응답 제어 X)

4. Lecture 08 — 객체지향 프로그래밍(OOP) ★ 기말 최핵심

🗣 13주차 교수님 (최상위 강조)
“이거 이해 안 되면 안 됩니다. 이해 안 되면 기말고사에 아무것도 [할] 수 없을 수 있어요.” — 이 절은 한 줄도 빠짐없이 손으로 써볼 것.

4-1. 객체(Object)와 클래스(Class)

파이썬의 모든 값은 객체이고, 모든 객체는 ① 타입 ② 내부 데이터 표현 ③ 상호작용용 메서드를 가진다. 1234는 int의 인스턴스, "hello"는 str의 인스턴스.

🐶 붕어빵 비유 (교수님)
클래스를 만든다 = “강아지란 눈·코가 있고 다리 4개고 이런 걸 할 수 있다”고 정의(틀)하는 것. 클래스를 사용한다 = 그 정의대로 실제 객체(인스턴스)를 찍어내는 것(개 10마리, 양 100마리). 붕어빵 틀(클래스) → 붕어빵들(인스턴스).

두 가지 속성

  • 데이터 속성(data attributes) — “객체가 무엇인가”(명사). 예: 좌표의 x, y / 동물의 age, name
  • 메서드(procedural attributes) — “객체가 무엇을 하는가”(동사). 이 클래스에서만 동작하는 함수. 예: 두 좌표 사이 거리 구하기

4-2. 클래스 정의 — Coordinate 예제 (통째로 암기)

class Coordinate(object):           # object 상속 → Coordinate는 object의 subclass
    def __init__(self, x, y):       # 생성자: 인스턴스 만들 때 자동 호출
        self.x = x                  # self = 지금 만들어지는 인스턴스 자신
        self.y = y                  # self.x, self.y = 인스턴스 변수
    def distance(self, other):      # 메서드: 첫 인자는 항상 self
        x_diff_sq = (self.x - other.x)**2
        y_diff_sq = (self.y - other.y)**2
        return (x_diff_sq + y_diff_sq)**0.5
    def __str__(self):              # print(객체)할 때의 문자열 표현
        return "<" + str(self.x) + "," + str(self.y) + ">"
# 사용(using the class)
c = Coordinate(3, 4)                # 인스턴스 생성 (self는 파이썬이 자동 전달)
origin = Coordinate(0, 0)
print(c.x)                          # 3  (점 표기로 데이터 속성 접근)
print(c.distance(origin))          # 5.0
print(c)                           # <3,4>   ← __str__ 덕분
print(type(c))                     # <class '__main__.Coordinate'>
print(isinstance(c, Coordinate))   # True
🔑 절대 헷갈리지 말 것
  • self = 메서드를 호출한 그 인스턴스. 정의할 때 첫 인자로 항상 써준다. 호출할 때는 self를 안 넘긴다(파이썬이 자동).
  • __init__ = 인스턴스 생성 시 자동 호출되는 초기화 함수. return 없음.
  • 점(.) 표기로 데이터 속성·메서드 모두 접근: c.x, c.distance(...).
  • 기본 print는 <__main__.Coordinate object at 0x...> 같이 무의미 → __str__로 원하는 표현 정의(override).

메서드 호출 — 두 방식은 동치 (교수님 강조)

c.distance(zero)                 # 관용적 방식 (self ← c)
Coordinate.distance(c, zero)     # 위와 완전히 동일 (self에 c를 직접 전달)

4-3. 특수 메서드 & 연산자 오버로딩

이중 밑줄(__ __) 특수 메서드를 정의하면 연산자를 내 클래스에 맞게 재정의(override)할 수 있다.

특수 메서드대응 연산
__add__(self, other)self + other
__sub__(self, other)self - other
__eq__(self, other)self == other
__lt__(self, other)self < other
__len__(self)len(self)
__str__(self)print(self)

예제: 분수(Fraction) 클래스

class Fraction(object):
    def __init__(self, numer, denom):   # 분자, 분모
        self.numer = numer
        self.denom = denom
    def __str__(self):
        return str(self.numer) + "/" + str(self.denom)
    def __add__(self, other):           # a/b + c/d = (ad+cb)/bd
        numerNew = self.numer*other.denom + other.numer*self.denom
        denomNew = self.denom*other.denom
        return Fraction(numerNew, denomNew)
    def convert(self):                  # float로 변환
        return self.numer / self.denom

f1 = Fraction(1, 2)
f2 = Fraction(1, 4)
print(f1 + f2)        # 6/8   ← __add__ 호출
print((f1 + f2).convert())   # 0.75
🔑 왜 OOP인가
데이터와 그 데이터를 다루는 함수를 한 묶음(패키지)으로 → 모듈화·재사용·복잡도 감소. 추상화로 “어떻게 구현했나”와 “어떻게 쓰나”를 분리(사용자는 인터페이스만 알면 됨). 파이썬 기본 클래스 위에 나만의 타입을 쌓을 수 있다.

📋 개념 Q&A — OOP

클래스를 “정의”하는 것과 “사용”하는 것의 차이는?
정의=틀(이름·데이터 속성·메서드)을 만드는 것. 사용=그 틀로 인스턴스를 생성하고 연산하는 것. (붕어빵 틀 vs 붕어빵)
self는 무엇인가? 호출할 때 넘겨주나?
메서드를 호출한 그 인스턴스 자신. 정의 시 첫 인자로 항상 쓰지만, 호출 시엔 안 넘긴다(파이썬이 자동 전달). c.distance(z) ↔ Coordinate.distance(c, z).
__init__의 역할과 특징은?
인스턴스 생성 시 자동 호출되어 데이터 속성을 초기화. 반환값이 없다.
__str__를 정의하는 이유는?
기본 print는 메모리 주소 같은 무의미한 표현을 보여줌. __str__로 print(객체) 시 출력할 문자열을 직접 정한다(override).
데이터 속성과 메서드의 차이는?
데이터 속성=객체가 무엇인지(상태, 명사). 메서드=객체가 무엇을 하는지(행동, 동사, 이 클래스 전용 함수).
c == d를 내 클래스에 맞게 동작시키려면?
__eq__(self, other) 특수 메서드를 정의(연산자 오버로딩). 마찬가지로 +는 __add__, <는 __lt__.

5-1. getter/setter · 정보 은닉 · 기본 인자

class Animal(object):
    def __init__(self, age):
        self.age = age
        self.name = None
    def get_age(self):          # getter: 데이터 속성 읽기
        return self.age
    def get_name(self):
        return self.name
    def set_age(self, newage):  # setter: 데이터 속성 쓰기
        self.age = newage
    def set_name(self, newname=""):   # 기본 인자(default argument)
        self.name = newname
    def __str__(self):
        return "animal:" + str(self.name) + ":" + str(self.age)
  • 클래스 밖에서는 데이터에 직접 접근(a.age)하지 말고 getter/setter 사용(a.get_age()) — 정보 은닉
  • 이유: 클래스 작성자가 내부 변수명을 바꿔도(self.age→self.years) 바깥 코드가 안 깨짐 → 유지보수↑·버그↓
  • 단, 파이썬은 정보 은닉이 약함: 밖에서 a.age='infinite'로 쓰거나 a.size="tiny"로 새 속성까지 만들 수 있다(나쁜 스타일이지만 가능)
  • 기본 인자: 인자 안 주면 기본값 사용. a.set_name()→"", a.set_name("fluffy")→"fluffy"

5-3. 클래스 변수 vs 인스턴스 변수 ★ (Rabbit)

🗣 15주차 — 주민등록번호 비유
“self가 없다는 거는 얘가 클래스 변수다 — 모든 인스턴스에서 공유되는 값. 붕어빵 틀에 번호를 매겨 1번·2번·3번 붕어빵을 구분하듯, 토끼마다 고유 id를 준다.” 
class Rabbit(Animal):
    tag = 1                         # ← 클래스 변수 (self 없음 = 모든 인스턴스 공유)
    def __init__(self, age, parent1=None, parent2=None):
        Animal.__init__(self, age)
        self.parent1 = parent1      # ← 인스턴스 변수 (각 객체마다 따로)
        self.parent2 = parent2
        self.rid = Rabbit.tag       # 현재 tag를 내 id로
        Rabbit.tag += 1             # 다음 토끼를 위해 1 증가
    def get_rid(self):
        return str(self.rid).zfill(3)   # 001, 002 ... (3자리 0채움)
    def get_parent1(self):
        return self.parent1
클래스 변수 (class variable)인스턴스 변수 (instance variable)
클래스 본문에 직접(tag = 1), self 없음self.parent1 = ..., self 있음
모든 인스턴스가 공유(하나의 값)객체마다 독립
Rabbit.tag로 접근self.rid로 접근

연산자 오버로딩 — Rabbit의 __add__, __eq__

    def __add__(self, other):
        # 두 토끼의 자식을 만든다: 나이 0, 부모는 self와 other
        return Rabbit(0, self, other)

    def __eq__(self, other):
        # 부모가 같으면 같은 토끼로 간주 (id로 비교 — id는 고유)
        parents_same = self.parent1.rid == other.parent1.rid \
                       and self.parent2.rid == other.parent2.rid
        parents_opposite = self.parent2.rid == other.parent1.rid \
                           and self.parent1.rid == other.parent2.rid
        return parents_same or parents_opposite
⚠ 왜 객체 직접 비교 대신 id로?
self.parent1 == other.parent1처럼 객체를 직접 비교하면 __eq__가 계속 재귀 호출되다 None에 도달해 None.parent1에서 AttributeError. 그래서 고유한 rid(클래스 변수로 부여)로 비교한다.

📋 개념 Q&A — 상속

subclass가 superclass로부터 물려받는 것은? 추가로 할 수 있는 일은?
부모의 모든 데이터 속성·메서드를 상속. 자식은 ① 새 속성/메서드 추가 ② 기존 메서드 오버라이드(재정의) 가능.
인스턴스에서 메서드를 부를 때 어떤 정의가 쓰이나?
현재 클래스부터 찾고 없으면 계층을 위로 올라가며 찾아 처음 발견한 메서드를 사용. → 자식이 정의했으면 자식 것이 우선.
자식 __init__에서 부모 초기화를 어떻게 하나?
Animal.__init__(self, age)처럼 부모 클래스명으로 호출하고 self를 직접 전달.
클래스 변수와 인스턴스 변수의 차이는?
클래스 변수(tag=1, self 없음)는 모든 인스턴스 공유. 인스턴스 변수(self.rid)는 객체마다 독립. Rabbit이 생길 때마다 Rabbit.tag가 1씩 증가해 고유 id 부여.
Cat(Animal)에 __init__이 없으면?
에러 아님 — 부모 Animal의 __init__이 그대로 사용된다(상속).
